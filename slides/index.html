Bloc 1 · Origine et philosophie

Pourquoi Python a-t-il été créé ?

Un peu d'histoire

  • Créé par Guido van Rossum aux Pays-Bas et publié en 1991.
  • Nommé en hommage à la troupe humoristique Monty Python's Flying Circus (et non au reptile !).
  • Conçu pour combler le fossé entre les scripts shell (rapides à écrire mais limités) et le langage C (puissant mais verbeux).
  • Aujourd'hui piloté par la Python Software Foundation (PSF) avec une version majeure chaque année (Python 3.12 / 3.13+).

Le « Zen de Python » (import this)

# Principes directeurs intégrés au langage :
"Ce qui est explicite vaut mieux que ce qui est implicite."
"Ce qui est simple vaut mieux que ce qui est complexe."
"La lisibilité compte."
"Il devrait y avoir une — et de préférence une seule —
 façon évidente de procéder."

Constat en TI : On passe 80 % de son temps à lire et maintenir du code existant, et 20 % à en écrire du nouveau.

Bloc 1 · Repères pour développeurs

Ce qui change par rapport à C#, Java et JavaScript

Concept C# / Java / JavaScript Python 🐍
Délimitation des blocs Accolades { ... } et point-virgule ; Deux-points : et indentation obligatoire (4 espaces)
Convention de nommage camelCase (variables/fonctions) snake_case (calculer_total, utilisateur_actif)
Valeur nulle / absence null (ou undefined en JS) None (objet unique de type NoneType)
Booléens et logique true / false, &&, ||, ! True / False (majuscule !), and, or, not
Point d'entrée Classe + méthode static void Main() Exécution directe de haut en bas (aucune classe requise) 
// En C# / Java / JS
if (estActif && tentatives < 3) {
    autoriserAcces();
}
# En Python : épuré et lisible
if est_actif and tentatives < 3:
    autoriser_acces()
Bloc 1 · Système de types

Typage dynamique, mais fort !

1. Dynamique (le type est lié à la valeur)

Pas besoin de déclarer le type d'une variable à l'avance. Une variable est une simple étiquette pointant vers un objet en mémoire.

compteur = 10          # int
compteur = "dix"       # str (valide !)

2. Fort (pas de conversion implicite piégeuse)

Contrairement à JavaScript, Python refuse d'additionner du texte et un nombre sans conversion explicite :

# En JavaScript : "5" + 5  --> "55" 😱
# En Python :
resultat = "5" + 5
# ❌ TypeError: can only concatenate str to str

resultat = int("5") + 5  # ✅ 10
Nouveauté moderne — Les annotations de type (type hints) : Depuis Python 3.5+, on peut annoter les types pour l'autocomplétion de l'IDE et l'analyse statique (similaire à TypeScript) : def calculer_rabais(prix: float, taux: float = 0.15) -> float:
Bloc 1 · Architecture d'exécution

Sous le capot : comment s'exécute Python ?

1. Code source

Fichier texte script.py écrit par le développeur

➔

2. Compilation

Traduction automatique en bytecode (__pycache__/*.pyc)

➔

3. Machine virtuelle

Exécution instruction par instruction par la VM CPython

Comparaison avec Java et C#

  • Comme la JVM (Java) ou le CLR (.NET), Python utilise du bytecode et un ramasse-miettes (garbage collector).
  • Différence clé : CPython vérifie les types dynamiquement à l'exécution et n'avait historiquement pas de compilateur JIT par défaut (contrairement à Java/C#/V8).

Le secret de vitesse des bibliothèques

  • Pourquoi l'IA tourne-t-elle en Python si CPython est lent ?
  • Parce que Python sert de chef d'orchestre : quand vous appelez NumPy ou PyTorch, le calcul lourd s'exécute en C, C++ ou Rust compilé !
Bloc 1 · Analyse critique

Les grandes forces de Python en TI

🚀 Productivité et vélocité

  • 3 à 5 fois moins de lignes de code qu'en Java ou C++ pour accomplir la même tâche.
  • Idéal pour le prototypage rapide, les preuves de concept (PoC) et les scripts d'automatisation.
  • Courbe d'apprentissage ultra-rapide pour toute l'équipe.

🔗 Langage « de colle » universel

  • S'interface nativement avec C, C++ et Rust.
  • Omniprésent sous Linux, macOS, Windows, Docker, AWS, GCP et Azure.
  • Incontournable en DevOps, cybersécurité, science des données et IA.
Exemple parlant : Lire un fichier JSON, filtrer des enregistrements et envoyer une requête HTTP prend moins de 10 lignes lisibles en Python, sans aucune classe ni configuration complexe.
Bloc 1 · Analyse critique

Les faiblesses et limites à connaître

🐢 Performance brute et mémoire

  • Exécution plus lente : Une boucle pure en Python peut être 10x à 50x plus lente qu'en C#, Rust ou C++.
  • Consommation mémoire : Chaque nombre ou objet en Python embarque des métadonnées lourdes.
  • Le GIL (Global Interpreter Lock) : Un verrou interne empêche un processus CPython standard d'exécuter du code Python sur plusieurs cœurs CPU en même temps via des threads.

📦 Déploiement et domaines peu adaptés

  • Erreurs découvertes à l'exécution : Sans compilateur strict, une faute de frappe dans une branche rare peut planter en production (d'où l'importance des tests et de mypy/ruff).
  • Distribution d'applications : Pas de petit binaire autonome natif ; distribuer un exécutable de bureau reste lourd.
  • À éviter pour : Applications mobiles natives (iOS/Android), moteurs de jeux 3D lourds, systèmes embarqués temps réel.

Formatage moderne avec les f-strings

Préfixez la chaîne par la lettre f pour insérer des expressions directement entre accolades { } :

print(f"Serveur : {serveur}:{port}")
# ➔ Serveur : prod-mtl-01:8080

# Formatage direct des décimales (.1f) :
print(f"Charge CPU : {charge_cpu:.1f} %")
# ➔ Charge CPU : 74.9 %
Bloc 3 · Structures conditionnelles 💻 Colab : Section 1.3

Conditions : if, elif, else

code_http = 404

if code_http == 200:
    statut = "Succès"
elif 400 <= code_http < 500:  # Comparaison chaînée !
    statut = "Erreur client"
elif code_http >= 500:
    statut = "Erreur serveur"
else:
    statut = "Autre réponse"

# Opérateur ternaire sur une ligne :
alerte = "Critique" if code_http >= 500 else "Normal"

Astuces « pythoniques » dans les conditions

  • Comparaisons chaînées : On peut écrire directement 0 <= note <= 100 au lieu de note >= 0 and note <= 100 !
  • Valeurs fausses (falsy) : 0, "" (chaîne vide), [] (liste vide), {} et None valent automatiquement False.
  • On écrit if erreurs: plutôt que if len(erreurs) > 0:.

Bloc 4 · Manipulation élégante 💻 Colab : Sections 2.1 & 2.2

Découpage (slicing) et déballage (unpacking)

1. Le découpage liste[début:fin:pas]

octets = [10, 20, 30, 40, 50]

octets[0]       # 10 (premier élément)
octets[-1]      # 50 (dernier élément !)
octets[1:4]     # [20, 30, 40] (indice 4 exclu)
octets[:2]      # [10, 20] (les 2 premiers)
octets[::-1]    # [50, 40, 30, 20, 10] (inversé !)

2. Le déballage (unpacking)

# Assignation multiple en une ligne

# Échanger deux variables sans variable temporaire
a, b = b, a

# Parcourir clés et valeurs d'un dictionnaire

Bloc 4 · Organisation du code 💻 Colab : Section 2.3

Fonctions : def, valeurs par défaut et retour multiple

def creer_compte(
    courriel: str,
    role: str = "lecteur",
    actif: bool = True
) -> dict:
    """Crée et retourne un profil utilisateur."""
    return {
        "courriel": courriel.lower(),
        "role": role,
        "actif": actif,
    }

# Appel par position ou par nom (keyword arguments) :
u1 = creer_compte("Lea@Exemple.ca")
u2 = creer_compte("marc@ti.qc.ca", actif=False, role="admin")

Retourner plusieurs valeurs

En Python, une fonction peut retourner un tuple qui est déballé directement par l'appelant :

def analyser_latence(mesures: list):
    minimum = min(mesures)
    maximum = max(mesures)
    moyenne = sum(mesures) / len(mesures)
    return minimum, maximum, moyenne

mini, maxi, moy = analyser_latence([12, 45, 18, 25])
Bloc 4 · Idiomes Python 💻 Colab : Sections 2.4 & 2.5

Écrire du code « pythonique » (Pythonic)

1. Compréhensions de liste (list comprehensions)

Remplace avantageusement map() / filter() ou LINQ :

latences = [15, 120, 42, 250, 18]

# Approche classique (4 lignes) :
alertes = []
for ms in latences:
    if ms > 100:
        alertes.append(f"{ms} ms")

# Approche pythonique (1 ligne) :
alertes = [f"{ms} ms" for ms in latences if ms > 100]

2. Gestion de ressources avec with

Équivalent du using en C# ou try-with-resources en Java — ferme automatiquement le fichier ou la connexion :

import json

with open("config.json", "r", encoding="utf-8") as f:
    config = json.load(f)
# Le fichier est déjà fermé proprement ici !
